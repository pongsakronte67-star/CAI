## 4. คู่มือติดตั้ง (10 ขั้น)

1. **สร้างโปรเจกต์ Supabase** เข้า supabase.com สมัครบัญชี แล้วกด New project ตั้งชื่อ (เช่น `nongsaeng-cai`) ตั้งรหัสผ่านฐานข้อมูลและจดเก็บไว้ เลือกภูมิภาคที่ใกล้ไทย (เช่น Singapore) รอจนสร้างเสร็จ
2. **ปิด Confirm email** ไปที่ Authentication → Sign In / Providers (หรือ Providers) → Email → ปิดตัวเลือก **Confirm email** แล้วกด Save (ชื่อเมนูอาจต่างเล็กน้อยตามเวอร์ชัน) ถ้าไม่ปิด นักเรียนจะสมัครแล้วเข้าระบบไม่ได้ เพราะอีเมลของนักเรียนเป็นอีเมลสมมติ
3. **รัน setup.sql** ไปที่ SQL Editor → New query → เปิดไฟล์ `setup.sql` คัดลอกทั้งไฟล์มาวาง → กด Run ต้องขึ้น Success ถ้ามีแถบสีแดง ให้ถ่ายภาพหน้าจอส่งผู้ดูแลระบบ (รันซ้ำได้ ไม่ลบข้อมูลเดิม)
4. **สร้างบัญชีผู้สอน** ไปที่ Authentication → Users → Add user → Create new user ใส่อีเมลจริงของครูและตั้งรหัสผ่าน ติ๊ก **Auto Confirm User** แล้วกลับไป SQL Editor รันบรรทัดนี้ (แก้อีเมลและชื่อ):
   `select public.add_teacher('อีเมลครู@gmail.com', 'ครูสมชาย');`
   สำคัญ: ต้องสร้างบัญชีครูก่อนเปิดให้ใครเข้าเว็บ
5. **ใส่ค่าเชื่อมต่อในไฟล์ courseware.html** ไปที่ Project Settings → API (หรือ Connect) คัดลอก **Project URL** และ **anon / publishable key** (ห้ามใช้ service_role) เปิด `courseware.html` ด้วย Notepad แก้ 3 บรรทัดบนสุดของส่วน `CFG`: `SUPABASE_URL`, `SUPABASE_ANON_KEY` และ `EMAIL_DOMAIN` (ใช้ค่าเดิมได้ ไม่ต้องมีอยู่จริง) แล้วบันทึก
6. **เปิดเว็บ** ทดลองดับเบิลคลิก `courseware.html` ในเบราว์เซอร์ (Chrome/Edge) หากจะให้นักเรียนใช้ที่บ้าน ให้นำไฟล์ขึ้นเว็บฟรี เช่น Netlify Drop (app.netlify.com/drop ลากไฟล์ไปวาง) หรือ GitHub Pages แล้วแจกลิงก์
7. **ใส่รายชื่อนักเรียนจริง** เข้าสู่ระบบแท็บ "ผู้สอน" → เมนู "รายชื่อ" → วางรายการ `รหัส 11 หลัก, ชื่อ-สกุล, ห้อง` บรรทัดละคน → กด นำเข้า
8. **ทดสอบกับรหัสทดสอบ** ใช้รหัส `99000000001` ผ่านแบบทดสอบระบบ (หัวข้อ 5) จากนั้นลบรายชื่อทดสอบ: หน้า "รายชื่อ" กด "ปล่อยรหัส" ที่รหัสที่ใช้ทดสอบ แล้วกด "ลบ" ทุกแถวที่ขึ้นต้น 990000000
9. **เตรียมเนื้อหา** เมนู "สื่อการเรียน" อัปโหลดไฟล์ประกอบบทเรียน และเมนู "งานที่มอบหมาย" ปรับหรือเพิ่มงาน (มีงานตัวอย่าง 2 งานมาให้)
10. **แจกวิธีใช้นักเรียน** บอกว่า: เข้าแท็บ "สมัครครั้งแรก" ใส่รหัส 11 หลักของตนเอง ตั้งรหัสผ่านอย่างน้อย 6 ตัวอักษร ครั้งต่อไปใช้แท็บ "เข้าสู่ระบบ" ถ้าลืมรหัสผ่านให้บอกครูกด "รีเซ็ตรหัสผ่าน" และควรกด "ส่งออก CSV" สำรองคะแนนเป็นระยะ

## 5. แบบทดสอบระบบ (15 ข้อ)

| # | ใคร | ทำอะไร | ผลที่ควรเห็น |
|---|---|---|---|
| 1 | ผู้สอน | รัน `setup.sql` ทั้งไฟล์ใน SQL Editor | ขึ้น Success ไม่มี error; ใน Table Editor เห็นตาราง roster, profiles, progress, quiz_questions ฯลฯ |
| 2 | นักเรียน | แท็บ "สมัครครั้งแรก" ใส่ `99000000001` ตั้งรหัสผ่าน 6 ตัวขึ้นไป | สมัครสำเร็จ เข้าหน้าหลักและเห็นชื่อ "นักเรียนทดสอบ 1" |
| 3 | นักเรียน | สมัครด้วยรหัสที่ไม่มีในรายชื่อ (เช่น `12345678901`) | ขึ้นข้อความ "ไม่พบรหัสนี้ในรายชื่อรายวิชา" และสมัครไม่ได้ |
| 4 | นักเรียน | ออกจากระบบ แล้วสมัครซ้ำด้วย `99000000001` | ขึ้น "รหัสนี้ถูกใช้สมัครแล้ว" |
| 5 | นักเรียน | ใส่รหัสสั้นกว่า 11 หลัก หรือรหัสผ่านสั้นกว่า 6 ตัว | ระบบปฏิเสธพร้อมข้อความภาษาไทย |
| 6 | นักเรียน | เข้าสู่ระบบด้วยรหัส + รหัสผ่านถูก แล้วลองรหัสผ่านผิด | ถูก: เข้าได้; ผิด: ขึ้น "รหัสนักเรียน/อีเมล หรือรหัสผ่านไม่ถูกต้อง" |
| 7 | นักเรียน | เปิดบทที่ 1 กด "ถัดไป" จนครบทุกหัวข้อ กลับหน้าหลักและรีเฟรช | ความก้าวหน้าบทที่ 1 = 100% และยังอยู่หลังรีเฟรช |
| 8 | นักเรียน | ทำแบบทดสอบบทที่ 1 ตอบครบแล้วส่ง | แสดงคะแนน x/5 พร้อมเฉลย/คำอธิบาย; หน้าหลักแสดง "คะแนนสอบสูงสุด" |
| 9 | นักเรียน | กดส่งแบบทดสอบโดยตอบไม่ครบ | ขึ้นเตือนให้ตอบครบ และไม่บันทึกคะแนน |
| 10 | นักเรียน | โปรไฟล์ → อัปโหลดรูป JPG/PNG ไม่เกิน 2 MB | รูปแสดงที่มุมบนขวา และยังอยู่หลังรีเฟรช; ไฟล์ใหญ่หรือไม่ใช่รูปถูกปฏิเสธ |
| 11 | นักเรียน | งานของฉัน → เลือกไฟล์ PDF/ภาพ กดส่งงาน | สถานะเป็น "ส่งแล้ว รอครูตรวจ" และเปิดไฟล์ที่ส่งได้; ไฟล์เกิน 10 MB ถูกปฏิเสธ |
| 12 | ผู้สอน | เข้าแท็บ "ผู้สอน" → ตรวจงาน → ให้คะแนน 8/10 + ความเห็น | นักเรียนเห็น "ตรวจแล้ว 8/10" และความเห็น และส่งงานใหม่ไม่ได้อีก; ใส่คะแนนเกินคะแนนเต็มไม่ได้ |
| 13 | ผู้สอน | สื่อการเรียน → อัปโหลดไฟล์ผูกกับบทที่ 1 | นักเรียนเห็นที่แท็บ "สื่อการเรียน" ของบทที่ 1 และเปิดได้; นักเรียนไม่มีปุ่มอัปโหลด/ลบ |
| 14 | นักเรียน 2 คน + ผู้สอน | สมัคร `99000000002` ทำแบบทดสอบ แล้วดูว่าเห็นงาน/คะแนนของคนแรกหรือไม่; ลองพิมพ์ `#/t/summary` ต่อท้ายลิงก์ | นักเรียนเห็นเฉพาะของตนเอง ถูกพากลับหน้าหลักเมื่อเข้าหน้าผู้สอน; ผู้สอนเห็นทั้งสองคนในสรุปผล |
| 15 | ผู้สอน | สรุปผล → ส่งออก CSV เปิดด้วย Excel; จากนั้นรายชื่อ → "รีเซ็ตรหัสผ่าน" ของคนทดสอบแล้วให้เขาเข้าด้วยรหัสใหม่ | ภาษาไทยอ่านได้ ตัวเลขตรงกับหน้าจอ; เข้าด้วยรหัสผ่านใหม่ได้ |

## 6. รายการที่ผู้สอนต้องตรวจเอง

**หมายเหตุสำคัญเรื่องการทดสอบ:** ไฟล์ทั้งสองยังไม่เคยถูกรันกับ Supabase จริง (ตรวจได้เฉพาะไวยากรณ์ JavaScript และความสอดคล้องของชื่อฟังก์ชัน/ตารางระหว่าง HTML กับ SQL) ให้ทำแบบทดสอบระบบทั้ง 15 ข้อก่อนใช้กับนักเรียน

### เนื้อหา
- [ ] รหัสวิชา ว20133 ชื่อวิชา และระดับชั้นตรงกับหลักสูตรสถานศึกษาของโรงเรียนหรือไม่ (ใช้ตามที่ระบุ ไม่ได้ตรวจกับเอกสารหลักสูตร)
- [ ] เนื้อหา 4 บทร่างขึ้นเองตามหัวข้อที่พบทั่วไปของวิทยาการคำนวณ ป.5 ไม่ได้อ้างอิงหนังสือเรียนเล่มใดหรือตัวชี้วัดข้อใด ต้องเทียบกับหน่วยการเรียนรู้และตัวชี้วัดจริง แล้วแก้ในตัวแปร `LESSONS` ของ `courseware.html`
- [ ] ตัวอย่างทำไข่ดาวมีการใช้เตาไฟ ตรวจว่าเหมาะกับวัยและแนวปฏิบัติความปลอดภัยของโรงเรียน
- [ ] ตัวอย่างผังงานและสัญลักษณ์ (วงรี สี่เหลี่ยมผืนผ้า ขนมเปียกปูน ลูกศร) ตรงกับที่สอนในชั้นเรียน
- [ ] ภาษา ความยาว และขนาดตัวอักษรเหมาะกับนักเรียน ป.5

### ข้อสอบ
- [ ] ข้อสอบ 20 ข้อ (บทละ 5 ข้อ) และเฉลยถูกต้อง ตรงกับสิ่งที่สอนจริง (เฉลยเก็บในตาราง `quiz_questions` แก้ได้ที่ Table Editor)
- [ ] เกณฑ์การใช้คะแนน: ระบบเก็บคะแนนสูงสุดและทำซ้ำได้ไม่จำกัด เฉลยแสดงหลังส่ง นักเรียนจึงจำเฉลยแล้วทำซ้ำได้ ถ้าใช้วัดผลจริงควรปรับ
- [ ] ข้อ L2-4 (โครงสร้างทำซ้ำ) และ L3-2 (สำรวจ/สอบถาม) อาจตีความได้หลายแบบ ตรวจคำถามและตัวเลือก
- [ ] งานตัวอย่าง 2 งาน (คะแนนเต็ม 10) เป็นเพียงตัวอย่าง ปรับให้ตรงกับแผนการสอน

### แหล่งอ้างอิง
- [ ] เนื้อหาไม่มีรายการอ้างอิง หากต้องการ ให้เพิ่มจากหนังสือเรียน/สื่อของ สสวท. ที่โรงเรียนใช้ และตรวจลิขสิทธิ์ของสื่อที่อัปโหลดเอง

### ข้อสมมติที่เสี่ยงผิด
- [ ] จำนวนผู้เรียนสมมติ 40 คน (ไม่มีผลต่อโค้ด) ต้องไม่เกินขีดจำกัดของแผนฟรี (ฐานข้อมูลและพื้นที่ไฟล์ จำกัดขนาด และโปรเจกต์ที่ไม่ได้ใช้งานนานอาจถูกพัก ตรวจเงื่อนไขปัจจุบันบนเว็บ Supabase)
- [ ] **รหัสนักเรียน 11 หลัก:** ใช้ตามโจทย์ ตรวจว่าตรงกับรหัสที่โรงเรียนใช้จริง และรหัสไม่ใช่ความลับ ใครรู้รหัสก็ชิงสมัครก่อนเจ้าของได้ ให้เปิดสมัครเฉพาะช่วงที่ครูอยู่ด้วย และตรวจสถานะ "สมัครแล้ว" ในหน้ารายชื่อ ถ้าถูกชิง ให้กด "ปล่อยรหัส" (ลบข้อมูลของบัญชีนั้นถาวร)
- [ ] ระบบตรวจรหัสก่อนสมัครบอกได้ว่ารหัสใดอยู่ในรายชื่อ (ไม่เผยชื่อ) ผู้ไม่หวังดีจึงเดารหัสได้
- [ ] **ผู้สอน:** ผ่อนจากโจทย์เล็กน้อยเพื่อความปลอดภัย: อีเมลที่ไม่ใช่ตัวเลข 11 หลักถูกข้ามตามโจทย์ แต่จะไม่ได้สิทธิ์ผู้สอนจนกว่าจะรัน `add_teacher` (ขั้น 4) ต้องสร้างบัญชีครูก่อนเปิดใช้งานจริง
- [ ] โดเมนอีเมลสมมติ `nongsaeng.example.com` เปลี่ยนได้ แต่ต้องใช้โดเมนเดียวกันตลอด หากเปลี่ยนหลังมีผู้สมัครแล้ว นักเรียนเดิมจะเข้าไม่ได้
- [ ] รหัสผ่านต่ำสุด 6 ตัวอักษร (ค่าเริ่มต้นของ Supabase) ถ้าต้องการยาวกว่านี้ ปรับที่ Authentication ของ Supabase และในหน้าเว็บ
- [ ] ความก้าวหน้าบันทึกจากฝั่งเบราว์เซอร์ นักเรียนที่เชี่ยวชาญอาจแก้ได้ จึงใช้เป็นข้อมูลประกอบเท่านั้น ส่วนคะแนนสอบตรวจที่เซิร์ฟเวอร์ แก้ไม่ได้
- [ ] "รีเซ็ตรหัสผ่าน" เขียนตรงลงตาราง auth ของ Supabase หากอัปเดต Supabase แล้วใช้ไม่ได้ ให้รีเซ็ตที่ Authentication → Users
- [ ] ไฟล์งานที่ส่งรับได้นามสกุล pdf, jpg, png, webp, doc(x), ppt(x), xls(x), txt, sb3, zip ไม่เกิน 10 MB ตรวจว่าครอบคลุมโปรแกรมที่ใช้ (เช่น Scratch .sb3) ตรวจนามสกุลที่หน้าเว็บ ไม่ได้ตรวจเนื้อไฟล์ที่เซิร์ฟเวอร์ ควรเปิดไฟล์ด้วยความระวัง
- [ ] ตาราง/มุมมองสรุปอ่านได้ไม่เกิน 1,000 แถวต่อครั้ง (ค่าเริ่มต้น Supabase) พอสำหรับ ~40 คน แต่หากมีงานหรือผู้เรียนมากขึ้น สรุปผลอาจไม่ครบ
- [ ] **ข้อมูลส่วนบุคคลของเด็ก (ชื่อ รูปโปรไฟล์ งาน):** ตรวจนโยบายโรงเรียนและการขอความยินยอมจากผู้ปกครองตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล และตำแหน่งเซิร์ฟเวอร์ที่เลือก
- [ ] การ "ปล่อยรหัส" ลบบัญชีและข้อมูลในฐานข้อมูลทั้งหมด แต่ไฟล์ที่เคยอัปโหลดอาจยังค้างใน Storage (ลบได้เองที่ Storage)
